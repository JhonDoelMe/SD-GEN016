# AGENT.md - Інструкція та Архітектура для ШІ-Агентів (SD-GEN016)

## 1. Загальний опис проєкту
**SD-GEN016** — це спеціалізований експлуатаційний веб-додаток (Service Desk) для оперативного обліку роботи бензинових та дизельних генераторів на об'єктах інфраструктури (АЗС, склади, офіси, медичні пункти тощо).

### Основні функції:
1. **Облік робочих циклів (мотогодини):**
   - Точний запуск і зупинка генератора оператором з фіксацією дати й часу у київському часовому поясі (`Europe/Kyiv`).
   - Підрахунок тривалості з точністю до секунд і накопичувальний підрахунок мотогодин.
2. **Багатооб'єктність та мультигенератори (Multi-site & Multi-generator):**
   - Підтримка кількох об'єктів (філій/локацій) та прив'язка генераторів і складів палива до конкретного об'єкта.
   - Система запам'ятовує останній вибір об'єкта та генератора для кожного користувача через `localStorage`.
3. **Паливний баланс:**
   - Рух палива: надходження на склад ГСМ (бензовоз) ➔ заправка бака генератора зі складу ГСМ ➔ списання за номінальним розходом.
   - Перевірка залишків, захист від від'ємного балансу.
4. **Регламентне ТО:**
   - Автоматичний розрахунок залишку мотогодин до наступного регламентного ТО (наприклад, кожні 300 годин).
   - Фіксація фактів проведеного ТО, попередження про необхідність обслуговування.
5. **Журнал несправностей:**
   - Реєстрація поломок та дефектів, зміна статусу генератора на `FAULTY` та блокування пуску до усунення.
6. **Звітність та експорт:**
   - Генерація зведених звітів за період, експорт детальних таблиць у формат Excel (`.xlsx`).
7. **Авторизація та безпека:**
   - JWT токени (Bearer header та захищені HTTP-Only кукі `access_token`).
   - Опція **«Запам'ятати мене»**: подовжена дія сесії (60 діб) у браузерах комп'ютерів, смартфонів та PWA додатку.
8. **Мобільний та десктопний інтерфейс (PWA):**
   - Адаптивна мобільна модель UI з великими тач-елементами (min 44–48px), великими шрифтами, захистом від небажаного авто-зуму на iOS (`font-size: 16px`).
   - Пропозиція встановлення веб-додатка при першому відвідуванні (PWA install prompt, iOS Safari guide).

## 2. Технологічний стек
- **Бекенд:** Python 3.11+, FastAPI, SQLAlchemy 2.0 (asyncio), SQLite (`aiosqlite`) за замовчуванням / PostgreSQL (`asyncpg`), Alembic, OpenPyXL, Pydantic v2, PyJWT, bcrypt.
- **Фронтенд:** Vanilla JavaScript (ES6+), HTML5, CSS3 (CSS Variables, Flexbox, CSS Grid, Safe Area Insets), Service Worker PWA (`sw.js`).
- **Тестування:** `pytest`, `pytest-asyncio`, `httpx`.

## 4. Правила та інструкції для агентів

### 4.1. Робота з часовим поясом (Timezone)
- Усі операції генератора, журнали та звіти прив'язані до часового поясу України: `Europe/Kyiv`.
- Використовуйте функції з `backend/app/core/timezone.py` для коректного переводу часу між UTC та локальним часом з урахуванням переходу на літній/зимовий час.
- На клієнті дати парсяться через `parseUTCDate()` та форматуються через `Intl.DateTimeFormat('uk-UA', { timeZone: 'Europe/Kyiv' })`.

### 4.2. Стан користувача та запам'ятовування (State Persistence)
- Останній вибраний об'єкт (`sd_last_facility_id`) та генератор (`sd_last_generator_id`, `sd_last_gen_facility_{id}`) зберігаються в `localStorage`.
- При завантаженні сторінки або зміні об'єкта вибір відновлюється автоматично, щоб оператор не вибирав їх щоразу наново.
- У разі видалення генератора ключ очищується з `localStorage`.

### 4.3. Авторизація та «Запам'ятати мене»
- Ендпоінт `/api/v1/auth/login` приймає `remember_me: bool`.
- При `remember_me=True` токен діє 60 днів, кукі `access_token` встановлюється з `max_age=5184000` (60 діб) та `samesite="lax"`, токен зберігається у `localStorage`.
- При `remember_me=False` токен діє стандартний час (24 години), токен зберігається у `sessionStorage`.
- Ендпоінт перевірки `/api/v1/auth/me` приймає як заголовок `Authorization: Bearer <token>`, так і кукі `access_token`, що гарантує підтримку мобільних браузерів, додатків і перезапусків.

### 4.4. Мобільний вигляд vs Десктопний вигляд
- Усі інтерактивні елементи на мобільних пристроях (кнопки, випадаючі списки `select`, вкладки, поля вводу) повинні мати мінімальну висоту **44–48 пікселів** (WCAG Touch Target Guidelines).
- Поля вводу (`input`, `select`) на мобільних повинні мати `font-size: 16px;`, щоб уникнути примусового авто-зуму в мобільному Safari на iOS.
- На мобільних екранах (`max-width: 768px`) панель вибору об'єкта та генератора має вертикальне групування зі зручними великими кнопками.
- Головна кнопка дії оператора (`#mainActionBtn`) повинна мати висоту не менше 60px та контрастні кольори (зелений для пуску, червоний для зупинки).

### 4.5. Тестування
- Завжди запускайте тести командою:
  ```bash
  python -m pytest
  ```
  Це гарантує, що коренева папка проєкту буде у `sys.path`.
- Додавайте тести до `backend/tests/` при зміні бекенд-логіки, схем або ендпоінтів.

### 4.6. Стандарти безпеки (Security Hardening)
- **Захист форм авторизації:**
  - Заборонено залишати дефолтні логіни або паролі у `value` чи `placeholder` в `frontend/index.html`.
  - Захист від Brute-Force: in-memory лімітер `check_login_rate_limit` блокує IP/логін на `LOGIN_LOCKOUT_SECONDS` (300 сек) після `LOGIN_MAX_ATTEMPTS` (5) невдалих спроб, повертаючи `429 Too Many Requests`.
  - Захист від Timing Enumeration: при відсутності користувача у БД виконується `verify_dummy_password()`, щоб час відповіді збігався з реальною перевіркою `bcrypt`.
- **Серверна валідація логінів та паролів:**
  - Логіни перевіряються регулярним виразом `^[a-zA-Z0-9_.\-]+$` (3–50 символів), унікальність перевіряється без урахування регістру (`func.lower`).
  - Паролі проходять перевірку складності (`validate_password_complexity`: від 8 до 128 символів, обов'язкова наявність літер та цифр, відсутність null-байтів).
- **Захист від SQL Injection, XSS та CSV/Excel Formula Injection:**
  - Усі запити до БД виконуються виключно через параметризовані вирази SQLAlchemy ORM. Динамічні імена таблиць у DDL/міграціях звіряються зі суворим білим списком (`allowed_facility_tables`, `serial_tables`).
  - У клієнтському коді (`frontend/app.js`) усі динамічні рядки перед вставкою в `innerHTML` обов'язково екрануються через `escapeHtml()`.
  - При генерації CSV та Excel звітів (`backend/app/services/report_service.py`) усі комірки проходять через `sanitize_spreadsheet_cell()` для блокування формульних ін'єкцій (`=`, `+`, `-`, `@`).
- **RBAC та захист від стороннього доступу:**
  - Модифікація об'єктів (`POST/PUT/DELETE /api/v1/facilities`) вимагає дозволу `generator:configure`.
  - Усі спискові ендпоінти мають обмеження параметра `limit` (`Query(..., ge=1, le=500)`).
  - Відповіді сервера містять захисні HTTP-заголовки (`Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`).

### 4.7. Git-процес
- Після виконання та перевірки змін завжди виконуйте коміт та пуш у основну гілку (`main`).

### 4.8. Стандарти звітів, підвалу та швидких налаштувань
- **Звіти виключно в Excel (.xlsx):**
  - Експорт звітів здійснюється виключно у форматі багатосторінкового Excel (.xlsx).
  - Експорт CSV вимкнено (ендпоінт `/api/v1/reports/export` повертає `400 Bad Request` із роз'ясненням).
  - Ролі `operator` та `viewer` обов'язково мають дозвіл `reports:export`.
  - Автоматична ширина колонок у згенерованих Excel файлах обмежується (максимум 50 символів), щоб запобігти помилкам відновлення у Microsoft Excel через ліміт ширини 255 символів.
- **Швидкі налаштування об'єктів та генераторів:**
  - У верхній панелі поруч з вибором об'єкта та генератора розташовані кнопки `⚙️`, що викликають модальні вікна швидкого редагування (`PUT /api/v1/facilities/{id}` та `PUT /api/v1/generator/{id}`).
- **Підвал та моніторинг сервера:**
  - Підвал сайту містить живий моніторинг стану сервера (`GET /api/v1/system/status`): навантаження CPU %, використання RAM (МБ та %), статус БД, час роботи (Uptime).
  - Містить посилання на Ліцензію MIT, Політику конфіденційності, Умови використання, GitHub репозиторій (`https://github.com/JhonDoelMe/SD-GEN016`).
  - Офіційний копірайтинг: `"Створено MAXI-UA LLC, 2026. Усі права захищенні. E-MAIL: maxiuallc@gmail.com"`.

### 4.9. Web Push сповіщення (VAPID)
- Реалізовано нативні Web Push сповіщення для PWA та Android (`pywebpush`, VAPID ключі).
- Підписки зберігаються у моделі `PushSubscription`.
- Підтримуються категорії: старт/стоп генератора, низький рівень палива (Warning $\le 30\%$, Critical $\le 10\%$), нагадування про регламентне ТО.
- **Суворе обмеження частоти ТО**: не більше 2 сповіщень про ТО на добу на генератор/пристрій для запобігання надмірному спаму.

### 4.10. Системні налаштування в базі даних та парсер цін WOG
- Усі динамічні налаштування зберігаються у таблиці `system_settings` (`SystemSettings`), а не у `.env`.
- Файл `.env` використовується лише для статичних конфігурацій (підключення БД, JWT ключ, первинний обліковий запис SuperAdmin).
- Реалізовано парсер цін АЗК WOG (`https://wog.ua/ua/fuels/`) з безпечним кешуванням та автоматичним підтягуванням ціни пального за літр при прибуткуванні.

### 4.11. Безпечне скидання та очищення бази даних (Clean DB)
- Доступне виключно адміністраторам (`POST /api/v1/system/reset`).
- Вимагає обов'язкового підтвердження точним кодовим словом `ОЧИСТИТИ` або `RESET`.
- Підтримує очищення окремого об'єкта або повної системи із збереженням облікових записів адміністраторів та записом в незмінний аудит.

### 4.12. Системні коригування з адресацією по складах та об'єктах
- Модель `SystemAdjustment` містить обов'язкові поля `facility_id` та `target_name`.
- Коригування залишків складів ГСМ (`FuelStock`) адресується за точним `stock_id`, а не за генератором.
- Форма коригування динамічно синхронізує об'єкт, категорію та цільовий елемент.
- Дозволено виключно SuperAdmin із обов'язковим зазначенням причини коригування.
