# AGENTS.md

Дивіться повний опис архітектури, правил та стандартів розробки для ШІ-агентів у файлі [AGENT.md](./AGENT.md).

## Обов'язкове правило Git-пушу (Multi-Remote Push to `main`)
По завершенню будь-якої задачі **ЗАВЖДИ** комітьте зміни та пуште їх у гілку `main` у **всі три віддалені репозиторії**:
- `origin` (`git push origin HEAD:main`)
- `gitlab` (`git push gitlab HEAD:main`)
- `codeberg` (`git push codeberg HEAD:main`)
(а також синхронізуйте локальну гілку `main`).

## Адаптація під ліміти запитів GitLab (Rate Limits & Push Pacing)
Згідно з регламентом [GitLab.com Rate Limits](https://docs.gitlab.com/user/gitlab_com/rate_limits/):
1. **Консолідація пушів (Zero Micro-Pushes):** Пушити код лише один раз по завершенню повної реалізації та локального тестування задачі. Уникатичастих мікро-пушів з інтервалом менше 1–2 хвилин.
2. **Локальна валідація до пушу:** Усі тести (`pytest`), перевірки безпеки (відсутність ключів/секретів у файлах) та узгодження версій мають бути успішно пройдені ДО виконання пушу, щоб уникати ланцюжків повторних пушів-виправлень.
3. **Заборона тимчасових віддалених гілок:** Не створювати та не видаляти короткоживучі тестові гілки безпосередньо на віддаленому `gitlab` — кожна така операція створює подвійне навантаження на Gitaly і викликає спрацювання burst-ліміту.
4. **Пауза охолодження (Cooldown & Backoff):** Якщо GitLab тимчасово блокує запити або повертає HTTP 429, обов'язково зачекати паузу охолодження не менше 60 секунд перед повторним зверненням.
