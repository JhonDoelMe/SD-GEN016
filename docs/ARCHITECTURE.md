# Архітектура системи: Service Desk Генератора (SD-GEN016)

**Версія архітектури:** 4.5.3 (YASNO Outages Integration, Audit Export & Multi-site Lockdown)  
**Дата оновлення:** 25 жовтня 2026 року  
**Розробник комплексу:** ТОВ «МАКСІ-ЮА» (MAXI-UA LLC)  

---

## 1. Загальний огляд системи

Програмний комплекс **SD-GEN016** спроектовано як високопродуктивну, відмовостійку, модульну багаторівневу систему промислового класу для оперативного обліку фактичної експлуатації генераторного обладнання критичної інфраструктури (АЗС, склади, медичні заклади, філії, автономні виробництва).

Система працює за гібридною напівавтоматичною моделлю: оператор або сервісний технік фіксує фактичні події (пуск, стоп, прийом палива, заправка, ТО, дефекти), а бекенд-сервіси забезпечують валідацію, криптографічну безпеку, сувору ізоляцію об'єктів (Варіант Б), захист інваріантів мотогодин та паливних залишків, незмінний аудит, Web Push сповіщення та звітність за стандартами **ДСТУ 4163:2020**.

## 3. Сутності та реляційні зв'язки (ORM Data Models)

1. **Facility (`facilities`)**: об'єкт інфраструктури (філія, АЗС, склад, медичний пункт) із власною адресою, часовим поясом та прив'язаними ресурсами.
2. **User (`users`)**: обліковий запис співробітника, що має прив'язку до об'єкта (`facility_id`), хеш пароля, статус активності та зв'язок з ролями.
3. **Generator (`generators`)**: генераторна установка, прив'язана до об'єкта (`facility_id`), із зазначенням місткості бака, нормативного розходу, потужності, поточних накопичувальних мотогодин та статусу.
4. **GeneratorRun (`generator_runs`)**: історія сеансів роботи (пуск, стоп, тривалість у секундах, початкові/кінцеві мотогодини, розрахунковий розхід палива, оператор).
5. **GeneratorSchedule (`generator_schedules`)**: добовий графік дозволеного часу запуску (наприклад 08:00–20:00 у зоні `Europe/Kyiv`).
6. **FuelStock (`fuel_stocks`)**: склад або резервуар палива, обов'язково закріплений за об'єктом (`facility_id`).
7. **FuelReceipt (`fuel_receipts`)**: надходження палива за чеком/накладною на конкретний склад.
8. **FuelTransfer (`fuel_transfers`)**: внутрішнє переміщення (заправка бака генератора зі складу того ж самого об'єкта).
9. **MaintenanceSchedule (`maintenance_schedules`)**: регламентний інтервал ТО генератора та контрольні лічильники напрацювання.
10. **MaintenanceRecord (`maintenance_records`)**: журнал проведеного обслуговування (регламентне або проміжне).
11. **Fault (`faults`)**: інциденти та дефекти обладнання.
12. **PushSubscription (`push_subscriptions`)**: зареєстровані Web Push підписки клієнтських браузерів з прив'язкою до `user_id` та валідацією endpoint.
13. **AuditLog (`audit_logs`)** та **SystemAdjustment (`system_adjustments`)**: незмінні реєстри аудиту та офіційних інвентаризаційних коригувань.
14. **Facility YASNO-поля** (розширення acilities, міграція Alembic `004_add_yasno_fields`): `yasno_enabled`, `yasno_region_id` (за замовчуванням 3), `yasno_dso_id` (за замовчуванням 301), `yasno_group` (`1.1`–`6.2`).

## 4. Фонові служби та інтеграція YASNO

- **`yasno_service.py`**: асинхронний клієнт API YASNO (`planned-outages`) з обходом WAF, перетворенням хвилинних слотів (0–1440) у погодинну карту та серверним кешем із TTL 15 хв. Відповідь містить `checked_at` (час перевірки, `Europe/Kyiv`) та `yasno_updated_on` (час публікації графіка оператором).
- **`run_yasno_checker_loop`**: фоновий цикл, що запускається у `lifespan` застосунку (`main.py`) і скасовується під час зупинки; за 25–35 хв до відключення (`DEFINITE` / `PROBABLE`) розсилає Web Push операторам об'єкта, дублювання у межах доби блокується (`notified_slots`).
- **Ендпоінт** `GET /api/v1/facilities/{id}/outage-schedule` повертає `Cache-Control: no-cache, no-store, must-revalidate`.
- **Експорт аудиту**: `GET /api/v1/audit/export-excel` (SuperAdmin) формує окрему книгу Excel з аркушами «Журнал дій аудиту» та «Системні коригування»; загальний звіт `GET /api/v1/reports/export-excel` більше не містить журналу аудиту.
