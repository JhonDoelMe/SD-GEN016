## 🚀 Ключові нововведення версії v4.5.0

### 1. Стартовий ланцюжок за замовчуванням (Default Chain Binding)
- **Суть проблеми:** При наявності декількох об'єктів, генераторів та складів ГСМ оператор міг випадково обрати склад з іншої філії або генератор, що не експлуатується на поточному об'єкті, що призводило до плутанини в паливних балансах.
- **Рішення:**
  - В системні налаштування (`SystemSettings`) додано параметри жорсткої прив'язки:
    $$\text{Об'єкт за замовчуванням} \longrightarrow \text{Генератор за замовчуванням} \longrightarrow \text{Склад ГСМ за замовчуванням}$$
  - При завантаженні системи або відкритті сесії інтерфейс автоматично активує цей ланцюжок.
  - Для операторів реалізовано автоматичну синхронізацію та валідацію: вибір незв'язаного складу чи генератора блокується, унеможливлюючи людські помилки при заправці та списанні.

### 2. Безпечне каскадне видалення об'єкта (Cascade Facility Deletion)
- **Суть проблеми:** При закритті філії чи переїзді об'єкта спроба видалення запису з бази даних блокувалася зовнішніми ключами (`ForeignKeyViolationError`) через наявність історії сеансів, залишків палива або записів коригувань (`system_adjustments`).
- **Рішення:**
  - В ендпоінт `DELETE /api/v1/facilities/{facility_id}` додано підтримку параметра `?cascade=true`.
  - Доступно **виключно головному адміністратору (SuperAdmin)**.
  - Сервер безпечно та послідовно очищує залежні сутності: склади ГСМ, генератори, сеанси напрацювання, ТО, несправності та зв'язані коригування інвентаризації в одній транзакції.
  - Операція обов'язково фіксується у незмінному реєстрі системного аудиту (`FACILITY_DELETE`).

### 3. Таргетування щотижневого звіту Excel (Weekly Digest Facility Scoping)
- **Суть проблеми:** Автоматична розсилка книги Excel керівництву щопонеділка формувалася за жорстко зашитим першим системним об'єктом (`facility_id = 1`), навіть якщо активна робота велася на іншій локації.
- **Рішення:**
  - Генератор звіту тепер враховує актуальний налаштований цільовий об'єкт організації (`default_facility_id` або явний `facility_id` у виклику `POST /system/email/weekly-digest/send`).
  - Листи та звіти для керівництва завжди містять точні фактичні дані активного об'єкта.

### 4. Адаптивний рідкий десктоп та мобільна панель навігації (Responsive UX)
- **Рідкий десктопний макет (Fluid Tiered Container):**
  - Плавне масштабування ширини контейнера робочої області (`1200px` ➔ `1260px` ➔ `1360px` ➔ `1420px`) на дисплеях із роздільною здатністю 1280px, 1440px та 1680px+.
  - Усунено обмеження вузького фіксованого контейнера, таблиці журналів та картки моніторингу заповнюють екран гармонійно та естетично.
  - Виправлено центрування перемикача об'єктів та генераторів у шапці для всіх екранів $\ge 769\text{px}$.
- **Мобільна нижня панель швидкої навігації (Bottom Navigation Bar):**
  - Для смартфонів та планшетів реалізовано фіксовану нижню панель навігації з 5 основними вкладками (*⚡ Головна, ⛽ Паливо, 🔧 ТО, ⚠️ Несправності, ⚙️ Меню*).
  - Ергономічне керування великим пальцем однієї руки безпосередньо біля генератора в польових умовах.
- **Оновлення брендингу:**
  - Шапку системи оновлено на офіційну назву: **⚡ Service Desk Генератора**.
  - Заголовок адмінки приведено до лаконічного стандарту: **⚙️ Системні налаштування**.

### 5. Скидання лічильника регламентного ТО (Admin Maintenance Reset)
- **Суть проблеми:** Коли планове регламентне ТО проводить виїзна сервісна служба (наприклад, заміна масла та фільтрів на 300, 600 чи 900 мотогодинах), вони часто повідомляють про це після відбуття, коли генератор вже напрацював додаткові години. Звичайний оператор не мав можливості ретроспективно зафіксувати точні години проведення ТО та перенести плановий інтервал.
- **Рішення:**
  - У вкладці «ТО» додано кнопку **«⚙️ Скидання лічильника ТО»** та окреме модальне вікно (відображається лише адміністраторам та суперадміністраторам).
  - Адміністратор вказує фактичні мотогодини проведення робіт (`operating_hours`), сервісну службу, використані матеріали та вартість робіт.
  - Сервер оновлює `last_performed_hours` та автоматично розраховує новий дедлайн:
    $$\text{next\_due\_hours} = \text{operating\_hours} + \text{interval\_hours}$$
  - Якщо генератор мав статус `MAINTENANCE_REQUIRED`, його статус повертається до робочого `STOPPED`.

### 6. Очищення історії надісланих сповіщень
- **Можливість:** У блоці **«📜 Журнал надісланих сповіщень»** додано кнопку **«🗑️ Очистити історію»**.
- **Безпека:** Доступно лише адміністраторам із обов'язковим діалогом підтвердження `confirm()`, серверним ендпоінтом `DELETE /api/v1/notifications/logs` та фіксацією події `NOTIFICATION_LOGS_CLEARED` у незмінному реєстрі аудиту.

### 7. Логічна реструктуризація панелі адміністратора
- Налаштування системи структуровано у 5 послідовних пронумерованих карток:
  1. *🏢 1. Організація, робочий регламент та часовий пояс*;
  2. *🔗 2. Стартовий ланцюжок за замовчуванням (Об'єкт ➔ Генератор ➔ Склад ГСМ)*;
  3. *⛽ 3. Табло цін АЗК WOG (із кнопкою оновлення цін)*;
  4. *⚙️ 4. Правила контролю витрати та блокування заправки*;
  5. *📬 5. Поштовий шлюз (SMTP) та автоматичні тижневі звіти*.
- Кнопку оновлення цін WOG перенесено безпосередньо в картку WOG, а деструктивну кнопку скидання БД інтегровано у блок бекапів (SuperAdmin Only).

## 🚀 Інструкція з розгортання оновлення на сервері (VPS)

Для оновлення працюючого сервера на версію `v4.5.0`:

```bash
# 1. Отримати свіжі зміни з гілки main
git checkout main
git pull origin main

# 2. Перезібрати Docker-образ без використання кешу
docker compose build --no-cache app

# 3. Перезапустити контейнери
docker compose up -d

# 4. Перевірити статус контейнерів та логи
docker compose ps
docker compose logs app --tail 30
```
