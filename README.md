Виробнича (production-ready) система оперативного обліку фактичної експлуатації бензинових та дизельних генераторів на об'єктах інфраструктури (підприємства, філії, АЗС, склади, медичні заклади, офісні центри тощо).

Система спроектована для надійної ручної та напівавтоматичної фіксації подій оператором і забезпечує прозору, безперервну та аудитовану історію:
**Об'єкти (Multi-site) → Генератори → Склади ГСМ → Мотогодини (онлайн та офлайн) → Рух палива → ТО (Регламентне / Проміжне) → Несправності → Сповіщення (Web Push) → Звітність (.xlsx) → Аудит та Системні коригування**.

---

## ⚡ Ключові можливості системи

### 1. Головна панель оператора (Dashboard)
- Великі кнопки **«ЗАПУСТИТИ»** / **«ЗУПИНИТИ»** із сенсорною оптимізацією для роботи біля генератора на смартфоні однією рукою (Touch Target min 48px).
- Моніторинг фактичного стану обладнання в реальному часі: *Зупинено, Працює, Потребує ТО, Несправний, Заблоковано*.
- Точний секундомір робочого циклу з автоматичним підрахунком орієнтовної витрати палива та накопичувальних мотогодин.
- **Офлайн-журнал та ретроспективне внесення**: можливість фіксації сесії роботи (`POST /api/v1/generator/manual-run`), якщо під час аварії був відсутній зв'язок або інтернет, з обов'язковою фіксацією причини в незмінному аудиті.

### 2. Багатооб'єктність та мультигенератори (Multi-site & Multi-generator)
- Підтримка кількох об'єктів (філій/локацій) та необмеженої кількості генераторів і складів ГСМ, закріплених за об'єктами.
- **Запам'ятовування вибору оператора**: автоматичне збереження та відновлення останнього обраного об'єкта та генератора (`localStorage`), що позбавляє від необхідності повторного вибору при кожному відкритті додатку.
- **Швидкі налаштування об'єкта та генератора**: кнопки швидкого редагування (`⚙️`) безпосередньо у шапці для оперативної зміни назви, локації, потужності, ємності бака та паспортного розходу.

### 3. Багатоскладовий облік палива (Склади ГСМ ↔ Бак генератора)
- Оприбуткування палива за чеком із розрахунком фактичної вартості за літр (грн/л), фіксацією постачальника, номера накладної та водія бензовоза.
- **Автоматичний парсинг цін АЗК WOG**: інтегрований автоматичний парсер актуальних роздрібних цін мережі WOG ([https://wog.ua/ua/fuels/](https://wog.ua/ua/fuels/)), який підставляє актуальну ринкову вартість пального, якщо ціну не вказано вручну в чеку.
- Переміщення палива (заправка) зі складу в бак конкретного генератора із захистом від від'ємних залишків та контролем місткості бака.
- Підтримка декількох складів ГСМ на одному об'єкті з різними видами палива (А-95 Mustang, ДП тощо).

### 4. Мобільні та десктопні Web Push сповіщення (PWA & Android)
- Повноцінна підтримка стандарту Web Push (протокол VAPID) без необхідності сторонніх платних сервісів.
- **Оперативні повідомлення на пристрої операторів та адміністраторів**:
  - Пуск та зупинка генератора із зазначенням тривалості циклу;
  - Попередження про зниження залишку палива: попереджувальний рівень ($\le 30\%$) та критичний залишок ($\le 10\%$);
  - Нагадування про наближення планового регламентного ТО;
  - Реєстрація аварій та критичних несправностей.
- **Суворий ліміт нагадувань про ТО**: системне обмеження **не більше 2 нагадувань про ТО на добу** на пристрій для запобігання спаму.
- **Окрема вкладка «🔔 Сповіщення»**: індивідуальне налаштування підписки для кожного пристрою, увімкнення/вимкнення окремих категорій подій та кнопка перевірки відправки тестового сповіщення.

### 5. Контроль робочого графіка та часу (Europe/Kyiv)
- Контроль дозволеного інтервалу роботи генератора на сервері (наприклад, 08:00–20:00).
- Безпековий пріоритет: **зупинка генератора дозволена у будь-який час доби**.
- Повний облік часового поясу України та сезонних переходів часу (`ZoneInfo("Europe/Kyiv")`).

### 6. Системні налаштування в базі даних (Admin Settings)
- **Повна де-статизація**: графік роботи, часовий пояс, тарифи та цінова політика зберігаються в базі даних (`SystemSettings`) та редагуються адміністратором через веб-інтерфейс у вкладці налаштувань.
- Файл оточення `.env` використовується виключно для статичних конфігурацій (підключення до БД, JWT секрет, первинний обліковий запис SuperAdmin).
- Кнопка **«🟢 Оновити ціни АЗК WOG»** для миттєвої актуалізації вартості пального за офіційними даними мережі АЗК.

### 7. Безпечне скидання та очищення бази даних (Clean DB / System Reset)
- Спеціальний функціонал очищення системи перед продажем об'єкта, передачею іншому власнику або введенням нового об'єкта в експлуатацію.
- Доступний **виключно головному адміністратору (SuperAdmin)**.
- Дворівневий захист: вибір режиму (очищення тільки обраного об'єкта чи скидання всієї системи) з обов'язковим введенням кодового слова **`ОЧИСТИТИ`** (або `RESET`).
- Гарантоване збереження облікових записів адміністраторів та надійна фіксація операції очищення в системному журналі аудиту.

### 8. Технічне обслуговування (ТО)
- **Регламентне ТО**: прив'язане до мотогодин (наприклад, кожні 100/250/300 год) із подовженням інтервалу до наступного сервісу.
- **Проміжне ТО**: заміна свічок, фільтрів, доливання оливи, очищення — фіксується в журналі, але **не збиває** регламентний лічильник годин.
- Функція автоматичного перерахунку та вирівнювання графіка ТО.

### 9. Журнал несправностей
- Пріоритетизація інцидентів (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
- Критичні дефекти переводять обладнання у стан `FAULTY` та блокують запуск до офіційного підтвердження усунення.
- Повний життєвий цикл дефекту: *Новий → Прийнято в роботу → В процесі → Очікування запчастин → Вирішено → Закрито*.

### 10. Системні коригування з розділенням по складах та об'єктах
- Можливість коригування показників за результатами інвентаризацій та звірок (мотогодини, залишок у баку, залишок на складі ГСМ, інтервали ТО).
- **Чітке розділення по складах та об'єктах**: модальне вікно дозволяє обрати конкретний об'єкт, сутність та цільовий елемент (конкретний склад палива або генератор) з відображенням його поточного значення.
- Дозволено **виключно головному адміністратору (SuperAdmin)** з обов'язковим зазначенням причини коригування (номер акта звірки, інвентаризаційний опис тощо).
- Таблиця історії коригувань містить детальні колонки: *Дата | Адміністратор | Об'єкт | Цільовий елемент (Склад/Генератор) | Сутність | Поле | Було | Стало | Причина*.

### 11. Єдині стандарти відображення та ДСТУ 4163:2020
- Уся система приведена до єдиного національного стандарту відображення інформації:
  - **Час та тривалість**: точний хронометраж `ГГ:ХХ:СС` у журналах сесій (наприклад, `02:59:15` або `00:00:24`), підсумковий людиночитаний вигляд `X год YY хв` на картках аналітики (`7 год 02 хв`).
  - **Дати**: словесно-числовий вигляд `ДД місяця РРРР р.` (`20 жовт. 2026 р.`) або `ДД.ММ.РРРР`.
  - **Грошові розрахунки**: гривні з копійками (`1 250,50 грн`).
  - **Паливо**: об'єми в літрах (`15,0 л`).
- Миттєвий зворотний зв'язок оператору при натисканні «Сформувати звіт»: інформаційне сповіщення та наочні підсумкові картки ключових показників безпосередньо під формою.

### 12. Експлуатаційна звітність та експорт (виключно Excel .xlsx)
- Зведені метрики за довільний діапазон дат або швидкі періоди (*Сьогодні, Тиждень, Місяць, 3 Місяці, Весь час*).
- Багатосторінковий професійний звіт у форматі **Excel (.xlsx)**:
  - **Вкладка 1: Зведення (KPI)** — ключові показники роботи, витрати палива та параметри генераторів;
  - **Вкладка 2: Напрацювання по днях** — щоденні підсумки та хронометраж запусків;
  - **Вкладка 3: Рух палива** — залишки на складах ГСМ, прибуткування та витрати;
  - **Вкладка 4: Журнал ТО** — регламентні та проміжні сервісні роботи;
  - **Вкладка 5: Несправності та аудит** — перелік інцидентів та журнал операцій.

### 13. Мобільна та десктопна ергономіка (PWA версія 4.1)
- Працює як повноцінний додаток на Android, iOS Safari, Windows та Linux.
- Оптимізована контрастна темна тема, комфортні випадаючі списки без збоїв відображення та прокрутки.
- Гарантоване синхронне заповнення селекторів вибору об'єктів та складів без затримок.

## 🛡️ Безпека та захист даних (Security Hardening)

- **Захист від перебору паролів (Brute-Force Lockout)**: блокування IP-адреси та логіна після 5 невдалих спроб на 300 секунд (`429 Too Many Requests`).
- **Захист від переліку користувачів (Timing Attack Mitigation)**: константний час перевірки фіктивного хешу (`verify_dummy_password`) при неіснуючому логіні.
- **Серверна валідація даних**: контроль складності паролів (мінімум 8 символів, літери та цифри), валідація логінів `^[a-zA-Z0-9_.\-]+$`, очищення HTML-тегів у ПІБ.
- **Захист від ін'єкцій**:
  - **SQLi**: 100% запитів через параметризовані вирази SQLAlchemy ORM;
  - **XSS**: обов'язкове екранування через `escapeHtml()` перед вставкою у DOM;
  - **Excel / Spreadsheet Injection**: санітизація небезпечних префіксів формул (`=`, `+`, `-`, `@`) у клітинках експорту.
- **Суворий контроль доступу (RBAC)**: матриця з 23 дозволів; системні коригування та скидання дозволені тільки SuperAdmin.
- **Захисні HTTP-заголовки**: `Content-Security-Policy` (CSP), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.

## 🚀 Швидкий запуск

### 1. Запуск у Docker (Рекомендовано для сервера / VPS)

```bash
# Клонування репозиторію
git clone https://github.com/JhonDoelMe/SD-GEN016.git
cd SD-GEN016

# Налаштування змінних оточення
cp .env.example .env

# Запуск контейнерів у фоновому режимі
docker compose up -d --build
```

Система автоматично розгорне:
- Бекенд FastAPI (порт 8000);
- Базу даних PostgreSQL 16 (порт 5432);
- Nginx Reverse Proxy з автоматичним налаштуванням HTTPS / SSL (порти 80, 443);
- Автоматично виконає міграції Alembic та створить обліковий запис головного адміністратора.

Доступ до системи:
- Веб-панель: `http://<IP-вашого-сервера>` або `https://<ваш-домен>`
- Swagger API документація: `http://<IP-вашого-сервера>:8000/docs`

**Дані для першого входу:**
- Логін: `superadmin`
- Пароль: `SuperAdminSecretPass123!` (або значення з вашого `.env`)

---

### 2. Локальний запуск (Development)

Вимоги: Python 3.11+ / 3.14+, SQLite або PostgreSQL.

```bash
# Встановлення залежностей
pip install -r backend/requirements.txt

# Налаштування .env
cp .env.example .env

# Застосування міграцій бази даних
alembic upgrade head

# Запуск серверу розробки
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

## 🧪 Автоматизоване тестування

Проект покритий повним набором автоматизованих тестів (`pytest`):
```bash
python -m pytest backend/tests -v
```

Повний набір із **45 тестів (100% Passed)** перевіряє:
1. **Аутентифікація та безпека**: вхід початкового суперадміна, валідація паролів, захист від брутфорсу (429 Lockout), блокування користувачів, HTTP-Only сесія «Запам'ятати мене», захисні HTTP заголовки;
2. **Рольовий доступ (RBAC)**: матриця з 23 дозволів, заборона несанкціонованого пуску/зупинки спостерігачем, права на керування об'єктами;
3. **Життєвий цикл генератора**: майстер початкового налаштування, онлайн пуск/зупинка, ретроспективне внесення офлайн-сесій (`/manual-run`), підрахунок напрацювання, безпека мотогодин;
4. **Контроль робочого графіка**: перевірка часового поясу Києва, дозвіл зупинки в будь-який час, серверні часові обмеження;
5. **Облік палива**: надходження палива за чеком, переміщення зі складу в бак, захист від від'ємних залишків;
6. **ТО та надійність**: регламентне та проміжне ТО, вирівнювання інтервалів, збереження історії обслуговування;
7. **Журнал дефектів**: реєстрація дефектів, зміна статусу генератора на `FAULTY` та блокування пуску до усунення;
8. **Системні коригування та аудит**: коригування мотогодин, коригування залишків складів ГСМ за ID, фільтрація історії коригувань за об'єктом, перевірка незмінного аудиту;
9. **Багатооб'єктність та звітність**: CRUD об'єктів, мультисклади, генерація та структура багатосторінкового Excel-звіту (5 аркушів);
10. **Системні налаштування та очищення БД**: збереження конфігурацій у БД, парсинг цін АЗК WOG, безпечне скидання даних за кодовим словом `ОЧИСТИТИ`;
11. **Web Push сповіщення**: генерація VAPID ключів, підписка/відписка, збереження налаштувань, тестові повідомлення, обмеження ТО $\le 2$ на добу;
12. **Вбудований бекап-центр та планувальник**: створення snapshot-архівів `.zip` (Повний або Тільки БД), перевірка контрольних сум SHA-256 та маніфесту даних, авторизоване завантаження, захист від Path Traversal, конфігурація фонового розкладу та автоматична ротація старих копій.

## 📦 Резервне копіювання та відновлення

### 1. Веб-інтерфейс та REST API (SuperAdmin Only)
- **Вкладка «Адміністрування» -> «Резервні копії системи (Бекапи)»**:
  - Створення архіву в один клік (Повний або Тільки БД).
  - Пряме завантаження `.zip` на комп'ютер адміністратора.
  - Налаштування фонового автобекапу за розкладом (Europe/Kyiv) із автоматичною ротацією (видаленням старих копій).
  - Детальна документація: [docs/BACKUP_AND_RESTORE.md](docs/BACKUP_AND_RESTORE.md).

### 2. Консольні утиліти (CLI)
Створення резервної копії вручну:
```bash
python scripts/backup.py
# або у Linux:
sh scripts/backup.sh
```

Відновлення з резервної копії:
```bash
python scripts/restore.py backups/backup_sd_gen016_YYYYMMDD_HHMMSS.tar.gz
# або у Linux:
sh scripts/restore.sh backups/backup_sd_gen016_YYYYMMDD_HHMMSS.tar.gz
```
