# Архітектура системи: Service Desk Генератора (SD-GEN016)

**Версія архітектури:** 4.1.0  
**Дата оновлення:** 20 жовтня 2026 року  
**Розробник комплексу:** ТОВ «МАКСІ-ЮА» (MAXI-UA LLC)  

---

## 1. Загальний огляд системи

Програмний комплекс **SD-GEN016** спроектовано як високопродуктивну, відмовостійку, модульну багаторівневу систему промислового класу для оперативного обліку фактичної експлуатації генераторного обладнання критичної інфраструктури (АЗС, склади, медичні заклади, філії, автономні виробництва).

Система працює за гібридною напівавтоматичною моделлю: оператор або сервісний технік фіксує фактичні події (пуск, стоп, прийом палива, заправка, ТО, дефекти), а бекенд-сервіси забезпечують валідацію, криптографічну безпеку, захист інваріантів мотогодин та паливних залишків, незмінний аудит, Web Push сповіщення та звітність за стандартами **ДСТУ 4163:2020**.

## 3. Сутності та реляційні зв'язки (ORM Data Models)

1. **Facility (`facilities`)**: об'єкт інфраструктури (філія, АЗС, склад, медичний пункт) із власною адресою, часовим поясом та прив'язаними ресурсами.
2. **Generator (`generators`)**: генераторна установка, прив'язана до об'єкта (`facility_id`), із зазначенням місткості бака, нормативного розходу, потужності, поточних накопичувальних мотогодин та статусу.
3. **GeneratorRun (`generator_runs`)**: історія сеансів роботи (пуск, стоп, тривалість у секундах, початкові/кінцеві мотогодини, розрахунковий розхід палива, оператор).
4. **GeneratorSchedule (`generator_schedules`)**: добовий графік дозволеного часу запуску (наприклад 08:00–20:00 у зоні `Europe/Kyiv`).
5. **FuelStock (`fuel_stocks`)**: склад паливно-мастильних матеріалів, закріплений за об'єктом, із зазначенням виду палива та поточного залишку.
6. **FuelReceipt (`fuel_receipts`)**: надходження палива на склад за чеком/накладною від постачальника з розрахунком ціни за літр та збереженням реквізитів водія.
7. **FuelTransfer (`fuel_transfers`)**: заправка зі складу ГСМ у бак генератора з фіксацією балансів до та після операції.
8. **MaintenanceSchedule (`maintenance_schedules`)**: плановий норматив ТО (наприклад кожні 300 год) та відмітка наступного обслуговування.
9. **MaintenanceRecord (`maintenance_records`)**: журнал проведених регламентних та проміжних ТО з деталізацією матеріалів, вартості та виконавця.
10. **Fault (`faults`)**: журнал дефектів обладнання з пріоритетами та статусом усунення.
11. **PushSubscription (`push_subscriptions`)**: зареєстровані пристрої операторів та адміністраторів для отримання VAPID Web Push сповіщень.
12. **NotificationLog (`notification_logs`)**: системний лог відправлених сповіщень.
13. **SystemSetting (`system_settings`)**: динамічні параметри системи у форматі ключ-значення (назва фірми, кешовані ціни WOG, перемикачі сповіщень, VAPID ключі).
14. **SystemAdjustment (`system_adjustments`)**: журнал офіційних коригувань показників SuperAdmin за результатами інвентаризацій.
15. **AuditLog (`audit_logs`)**: незмінний транзакційний журнал дій усіх користувачів.
16. **User (`users`)**, **Role (`roles`)**, **Permission (`permissions`)**: модель гнучкого рольового доступу (RBAC).

## 4. Ключові архітектурні інваріанти та рішення

### 4.1. Автономне збереження стану клієнта (Client State Persistence)
Клієнтський код автоматично синхронізує обраний об'єкт та генератор через `localStorage` (`sd_last_facility_id`, `sd_last_generator_id`). При перемиканні вкладок чи перезапуску смартфона оператор повертається до свого обладнання без необхідності повторного вибору.

### 4.2. Робота в умовах блекаутів та відсутності зв'язку (Offline First)
PWA додаток кешує графічний інтерфейс через Service Worker (`v4.1`). У разі відсутності інтернету оператор фіксує дані на папері, а після відновлення зв'язку вносить сеанс через спеціалізований ендпоінт `/api/v1/generator/manual-run`.

### 4.3. Динамічна конфігурація без перерозгортання
Усі операційні параметри (графік, ціни палива, ліміти сповіщень, VAPID ключі) зберігаються в базі даних та синхронно кешуються в пам'яті бекенду (`RUNTIME_SETTINGS`). Файл `.env` залишається суворо статичним.

### 4.4. Стандарти звітності ДСТУ 4163:2020 та безпека експорту
- Експорт здійснюється виключно у 5-сторінковий **Excel (.xlsx)**;
- Формати чисел та дат повністю відповідають українським стандартам діловодства;
- Усі рядки проходять через санітизатор `sanitize_spreadsheet_cell` для виключення Formula Injection;
- Ширина колонок програмно обмежується до 50 символів для запобігання помилкам переповнення у Microsoft Excel.
