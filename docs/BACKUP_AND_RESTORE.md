# Резервне копіювання та відновлення даних (Backup & Disaster Recovery)

Система **SD-GEN016** підтримує багаторівневе резервне копіювання:
1. **Вбудований веб-модуль SuperAdmin UI & API**: створення архівів в один клік, завантаження на ПК оператора, налаштування фонового автобекапу за розкладом та автоматична ротація (видалення старих копій).
2. **Консольні CLI-скрипти**: для автоматизації на рівні хостової ОС через `cron` або CI/CD pipelines.

---

## 1. Вбудований бекап-центр у Веб-інтерфейсі (SuperAdmin Only)

У вкладці **«⚙️ Адміністрування»** для користувачів із роллю **Головний адміністратор (SuperAdmin)** доступний окремий блок: **«💾 Резервні копії системи (Бекапи)»**.

### 1.1. Можливості веб-інтерфейсу
- **➕ Створити бекап зараз**:
  - **Повний бекап (`full`)**: містить повний дамп усіх 20 реляційних таблиць БД у форматі JSON (`database_export.json`), фізичну базу SQLite (`service_desk.db`), папку фотографій чеків і дефектів (`uploads/`), а також маніфест цілісності `manifest.json` із хеш-сумами SHA-256 та лічильниками записів.
  - **Тільки база даних (`db_only`)**: швидкий компактний зліпок виключно реляційних даних без медіафайлів.
  - **Коментар/примітка**: можливість зафіксувати причину створення зліпка (напр. *«Перед плановим ТО генератора №1»*).
- **📥 Завантаження на робоче місце**: скачування сформованого `.zip` архіву безпосередньо через браузер із авторизацією.
- **🗑️ Видалення застарілих копій**: безпечне видалення з підтвердженням та захистом від Path Traversal.
- **⚙️ Розклад автобекапу**:
  - Увімкнення/вимкнення щоденного фонового демона.
  - Налаштування часу спрацьовування за часовим поясом Києва (`Europe/Kyiv`).
  - Вибір періодичності: щодня (`daily`) або щотижня (`weekly`).
  - Політика збереження (ротація): збереження $N$ найновіших копій (за замовчуванням 7).

## 2. Специфікація REST API (/api/v1/backups)

Усі ендпоінти захищені та вимагають ролі `is_superadmin = True`:

| Метод | Ендпоінт | Опис |
| :--- | :--- | :--- |
| `GET` | `/api/v1/backups` | Отримання списку наявних архівів, загального обсягу та метаданих |
| `POST` | `/api/v1/backups` | Створення нового бекапу (`{"type": "full" \| "db_only", "note": "..."}`) |
| `GET` | `/api/v1/backups/{filename}/download` | Потокове завантаження ZIP-архіву |
| `DELETE` | `/api/v1/backups/{filename}` | Безпечне видалення файлу бекапу |
| `GET` | `/api/v1/backups/settings` | Перегляд поточних параметрів автобекапу та розкладу |
| `PUT` | `/api/v1/backups/settings` | Оновлення параметрів автобекапу (час, частота, ротація) |

### Структура архіву `backup_{type}_{timestamp}.zip`:
```text
backup_full_20261021_030000.zip
├── manifest.json            # Версія, тип, автор, SHA-256 хеші, кількість рядків
├── database_export.json     # Повний дамп усіх 20 таблиць БД (JSON)
├── service_desk.db          # Фізичний файл SQLite бази даних
└── uploads/                 # Завантажені фотографії чеків, накладних та дефектів
    ├── receipts/...
    └── faults/...
```

## 3. Створення резервної копії через консоль (CLI)

### За допомогою Python (кросплатформно):
```bash
python scripts/backup.py
```

### За допомогою Shell (на Linux / VPS):
```bash
sh scripts/backup.sh
```

---

## 4. Відновлення системи з резервної копії

### За допомогою Python:
```bash
python scripts/restore.py backups/backup_sd_gen016_20261005_135700.tar.gz
```

### За допомогою Shell:
```bash
sh scripts/restore.sh backups/backup_sd_gen016_20261005_135700.tar.gz
```

Скрипт відновлення:
1. Перевіряє цілісність архіву.
2. Відновлює файл бази даних або застосовує SQL-дамп PostgreSQL.
3. Повертає директорію завантажених фотографій `uploads/`.
4. Перезапускає контейнери додатку (`docker compose restart app`).
