## 2. Категорії та склад даних, що обробляються Системою

Система обробляє такі групи даних:

### 2.1. Облікові та ідентифікаційні дані персоналу (Користувачі)
- **Службовий логін (Username):** унікальний буквено-цифровий ідентифікатор (3–50 символів);
- **Прізвище, ім'я, по батькові (ПІБ) та посада:** для персоніфікації записів у журналах пусків, накладних прийому палива, актах ТО, відомостях інвентаризації та аудиті;
- **Опційний аватар профілю (`.webp`):** завантажене користувачем або адміністратором фото профілю, оптимізоване у формат `.webp` без EXIF-метаданих та захищене авторизацією на маршруті `/uploads/avatars/*`;
- **Адреса електронної пошти (Email):** службовий контакт для сповіщень, тижневих дайджестів (з 1-click відпискою RFC 8058) та відновлення доступу;
- **Хеш службового пароля:** зберігається виключно у вигляді незворотного криптографічного хешу за алгоритмом **bcrypt** (12 раундів у production); відкриті паролі ніколи не фіксуються, не зберігаються і не потрапляють у логи;
- **Службова роль та матриця повноважень (RBAC):** перелік наданих дозволів (`superadmin`, `admin`, `operator`, `viewer`).

### 2.2. Технічні, сесійні та офлайн-дані (PWA / Android APK / IndexedDB)
- **Мережева адреса (IP-адреса):** фіксується при кожній авторизації, зміні пароля, операціях запуску/зупинки та коригування даних;
- **Ідентифікатор браузера / пристрою (User-Agent):** використовується для розпізнавання платформи (PWA, Android APK Capacitor, iOS Safari, Desktop);
- **Токени автентифікації (JWT):** короткострокові (24 год) або довгострокові (60 діб «Запам'ятати мене»); відкликані токени персистентно зберігаються у таблиці `revoked_tokens` (міграція `010`);
- **Технічні Cookie та Local Storage / IndexedDB:** `access_token` (`HttpOnly`, `SameSite=Lax`, `Secure`), параметри вибору об'єкта/генератора/теми у `localStorage` та локальна база **`IndexedDB` (`sd_gen016_offline`)** — для кешу довідників (`read_cache`) і відкладеної черги операцій без зв'язку (`mutation_queue` з ключем `idempotency_key`, без стороннього трекінгу).

### 2.3. Push-сповіщення (Web Push VAPID, Android FCM HTTP v1) та Центр сповіщень («🔔»)
- **Web Push підписки (RFC 8291, 8292):** `endpoint`, `p256dh`, `auth` з автосинхронізацією (`pushsubscriptionchange`);
- **Android Native Push Tokens (FCM HTTP v1):** реєстраційні токени Firebase Cloud Messaging для нативного мобільного додатку Android APK (`fcm_subscriptions`, без рекламних SDK чи сторонніх трекерів);
- **Центр сповіщень (`🔔`) та відмітки прочитання:** персональні позначки прочитаних повідомлень (`notification_reads`) у БД та живий браузерний Watcher за тегом `sd-log-{id}`;
- **Категорії сповіщень:** пуск/стоп генератора, аварійна/автоматична зупинка, пульс-нагадування, низький рівень пального, регламентне ТО, критичні несправності, планові відключення YASNO та повітряні тривоги / відбої (`AIR_ALERT_START`, `AIR_ALERT_END`).

### 2.4. Виробничі, технічні та локаційні дані обладнання
- **Об'єкти та локації:** назва філії/об'єкта, фізична адреса об'єкта, прив'язані склади палива та генераторні установки;
- **Параметри генератора:** марка, модель, серійний заводський номер, номінальна потужність (кВт), місткість бака (л), нормативний погодинний витрата палива (л/год), поточний статус роботи;
- **Журнал напрацювання (Мотогодини):** початкові та кінцеві покази лічильника (одометра), дата і час пуску/зупинки, точна тривалість циклу у секундах, розрахункова витрата пального;
- **Складський та фінансовий рух ПММ:** об'єм поставки (л), загальна вартість за чеком (грн), розрахункова ціна за літр (грн/л), номер ТТН / чека, ПІБ водія бензовоза, назва складу ПММ, об'єм заправки в бак;
- **Технічне обслуговування (ТО):** вид сервісу (регламентне за мотогодинами або проміжне), дата, перелік виконаних робіт, використані запчастини/олива, вартість робіт, ПІБ виконавця;

### 2.5. Мультимедійні вкладення (Фотофіксація)
- Фотографії фіскальних чеків, накладних, актів виконаних робіт;

## 4. Заходи захисту інформації та технічна безпека

Розробником впроваджено комплекс організаційних та технічних заходів кіберзахисту:

4.1. **Шифрування та криптографія:**
- Усі мережеві з'єднання шифруються за протоколами **TLS 1.2 / TLS 1.3**;
- Паролі користувачів захищені алгоритмом **bcrypt** (стійким до атак за допомогою GPU);
- Токени авторизації підписуються криптографічним ключем високої ентропії (256-бітний HMAC-SHA256);
- Push-повідомлення шифруються за стандартом **ECDH на еліптичній кривій P-256**.

4.2. **Захист від мережевих та прикладних атак:**
- **Rate Limiting та Lockout:** тимчасове блокування IP-адреси та облікового запису на 300 секунд після 5 поспіль невдалих спроб входу;
- **Захист від переліку користувачів (Timing Attack Mitigation):** стабільний час серверної відповіді навіть при неіснуючому логіні;
- **Захист від SQL-ін'єкцій:** використання суворо типізованих параметризованих ORM-запитів (SQLAlchemy 2.0);
- **Захист від XSS та Formula Injection:** примусове санітизування вхідних рядків (`escapeHtml`) та очищення небезпечних префіксів формул (`=`, `+`, `-`, `@`) при експорті таблиць;
- **Політика заголовків безпеки:** використання суворих HTTP-заголовків `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.

4.3. **Ізоляція даних та захист прав доступу (RBAC):**
- Доступ до модулів системи регулюється на рівні серверних залежностей;
- Рядові оператори позбавлені можливості редагувати або видаляти історичні записи;
- Доступ до системних коригувань залишків обмежений виключно роллю `superadmin` з обов'язковою фіксацією номера документа чи акта інвентаризації.

5.2. **Журнали пусків, паливного руху та ТО:** зберігаються не менше **3 років** (за замовчуванням — до 7 років відповідно до правил податкового та виробничого обліку України).

## 8. Політика використання файлів Cookie, Local Storage та IndexedDB

8.1. Система використовує виключно **функціональні та технічні** файли cookie, параметри `localStorage` та локальне сховище `IndexedDB`.  
8.2. Система **НЕ використовує** сторонні маркетингові, відстежувальні чи рекламні трекери (Google Analytics, Meta Pixel тощо).  
8.3. Використані технічні маркери та локальні сховища:
- `access_token` (Cookie / Bearer Header) — забезпечення захищеної сесії оператора;
- `sd_last_facility_id` (`localStorage`) — запам'ятовування поточної філії/об'єкта для зручності оператора;
- `sd_last_generator_id`, `sd_last_gen_facility_{id}` (`localStorage`) — запам'ятовування обраного генератора для об'єкта;
- `sd_theme_preference` (`localStorage`) — збереження обраної світлої/темної або автоматичної теми;
- `sd_last_seen_notif_id` (`localStorage`) — дедуплікація живих сповіщень у відкритому браузері;
- `sd_gen016_offline` (`IndexedDB`) — кеш останніх довідників об'єкта (`read_cache`) та черга несинхронізованих офлайн-операцій (`mutation_queue`).
