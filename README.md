Виробнича (production-ready) система оперативного обліку фактичної експлуатації бензинових та дизельних генераторів на об'єктах інфраструктури.

Система спроектована для надійної ручної та напівавтоматичної фіксації подій оператором і забезпечує прозору, безперервну та аудитовану історію:
**Об'єкти (Multi-site) → Генератори → Експлуатація → Мотогодини → Паливо (Склад ГСМ ↔ Бак) → ТО (Регламентне / Проміжне) → Несправності → Звітність (.xlsx) → Аудит**.

---

## ⚡ Ключові можливості

1. **Головна панель оператора (Dashboard)**:
   - Кнопки «ЗАПУСТИТИ» / «ЗУПИНИТИ» із сенсорною оптимізацією для роботи біля генератора на смартфоні однією рукою.
   - Живий моніторинг стану: *Остановлен, Работает, Требуется ТО, Неисправен, Заблокирован*.
   - Точний секундомір робочого циклу з автоматичним підрахунком орієнтовної витрати палива та накопичувальних мотогодин.
2. **Багатооб'єктність та мультигенератори (Multi-site & Multi-generator)**:
   - Підтримка кількох об'єктів (філій/локацій) та необмеженої кількості генераторів і складів ГСМ.
   - **Запам'ятовування вибору користувача**: система автоматично зберігає та відновлює останній обраний об'єкт та генератор (`localStorage`), позбавляючи потреби повторного вибору при кожному відкритті додатку.
   - **Швидкі налаштування об'єкта та генератора**: безпосередньо в рядку перемикання додано кнопки швидкого редагування (`⚙️`) для миттєвої зміни назви, локації, потужності, ємності бака та паспортного розходу без переходу в адміністративну панель.
3. **Контроль робочого графіка та часу (Europe/Kyiv)**:
   - Дозволений період роботи (наприклад, 08:00–20:00) перевіряється на сервері.
   - Зупинка генератора дозволена у будь-який час (безпековий пріоритет).
   - Повний облік часового поясу України та переходів літній/зимовий час (`ZoneInfo("Europe/Kyiv")`).
4. **Роздільний облік палива**:
   - Склад ГСМ ↔ Бак генератора.
   - Оприбуткування палива за чеком із розрахунком ціни за літр (грн/л) та фіксацією водія бензовоза / постачальника.
   - Захист від від'ємних залишків, контроль місткості бака генератора.
5. **Технічне обслуговування (ТО)**:
   - **Регламентне ТО**: прив'язане до напрацювання (наприклад, кожні 300 год) із подовженням інтервалу.
   - **Проміжне ТО**: заміна свічок, фільтрів, очищення — **не скидає** регламентний інтервал і лічильник годин.
   - Функція автоматичного перерахунку графіка ТО з урахуванням фактичних мотогодин.
6. **Журнал несправностей**:
   - Пріоритети (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
   - Критичні дефекти переводять генератор у стан `FAULTY` та блокують запуск до підтвердження усунення.
   - Життєвий цикл: *NEW → ACCEPTED → IN_PROGRESS → PENDING → RESOLVED → CLOSED*.
7. **Мобільна та десктопна моделі інтерфейсу (PWA)**:
   - Адаптивний UI, оптимізований під пальцевий ввід (WCAG Touch Target min 44–48px), великі шрифти та поля вводу без небажаного авто-зуму на iOS (`font-size: 16px`).
   - **Пропозиція встановлення додатку**: автоматичний банер встановлення PWA при першому візиті та покрокова інструкція для користувачів Apple iOS Safari.
8. **Авторизація та функція «Запам'ятати мене»**:
   - Можливість довготривалого збереження сесії (до 60 діб) у браузерах комп'ютерів, смартфонів та PWA через захищені HTTP-Only кукі та JWT токени.
9. **Аналітична звітність та експорт (виключно Excel .xlsx)**:
   - Зведені метрики за довільний період або швидкі пресети (Сьогодні, Тиждень, Місяць, Квартал, Весь час).
   - Багатосторінковий професійний звіт у форматі **Excel (.xlsx)**:
     - Вкладка 1: KPI Дашборд та параметри обладнання;
     - Вкладка 2: Звіт по днях і цикли напрацювання;
     - Вкладка 3: Рух палива та залишки на складах ГСМ;
     - Вкладка 4: Журнал регламентних та проміжних ТО;
     - Вкладка 5: Журнал несправностей та аудит операцій.
   - Експорт CSV повністю вимкнено за стандартом проекту для запобігання втрати форматування та помилок кодування.
10. **Підвал сайту та живий моніторинг сервера**:
    - Індикатори стану сервера в реальному часі: навантаження CPU (%), використання RAM (МБ та %), статус з'єднання з базою даних, Uptime (час безперервної роботи).
    - Швидкий доступ до Ліцензії, Політики конфіденційності, Умов використання та GitHub репозиторію.
    - Офіційний копірайтинг: `"Створено MAXI-UA LLC, 2026. Усі права захищенні. E-MAIL: maxiuallc@gmail.com"`.
11. **Незмінний аудит та системні коригування**:
    - Будь-яка дія протоколюється в журналі аудиту (`audit_logs`) з фіксацією IP, користувача та параметрів.
    - Системні коригування дозволені **виключно головному SuperAdmin** з обов'язковою фіксацією причини зміни, старого та нового значень.

## 🛡️ Безпека та захист даних (Security Hardening)

У системі реалізовано комплексний багаторівневий захист:

* **Захист від перебору паролів (Brute-Force & Credential Stuffing)**:
  - Автоматичний лімітер невдалих спроб входу за IP-адресою та логіном (`LOGIN_MAX_ATTEMPTS = 5`, блокування на `LOGIN_LOCKOUT_SECONDS = 300` сек з кодом `429 Too Many Requests` та заголовком `Retry-After`).
  - Фіксація спроб перебору в журналі аудиту (`AUTH_LOGIN_LOCKED`).
* **Захист від переліку користувачів (Timing Attack Mitigation)**:
  - При запиті з неіснуючим логіном виконується константна за часом перевірка фіктивного хешу (`verify_dummy_password`), що унеможливлює визначення наявності акаунта за затримкою відповіді сервера.
* **Серверна валідація логінів та паролів**:
  - Валідація логіна регулярним виразом `^[a-zA-Z0-9_.\-]+$` (3–50 символів). Блокування лапок, ін'єкцій, пробілів та спецсимволів.
  - Регістронезалежний контроль унікальності облікових записів (`func.lower(User.login)`).
  - Валідація складності паролів (`validate_password_complexity`): мінімум 8 символів (до 128), обов'язкова комбінація літер і цифр, заборона нульових байтів (`\x00`).
  - Серверне очищення та відхилення HTML-тегів (`<`, `>`) у полях ПІБ та email.
* **Захист від ін'єкцій (SQLi, Stored/Reflected XSS, Formula Injection)**:
  - **SQL Injection**: 100% запитів виконуються через параметризовані вирази SQLAlchemy ORM. Усі DDL-оновлення схеми перевіряють назви таблиць за строгим білим списком.
  - **XSS (Cross-Site Scripting)**: у клієнтському JavaScript усі динамічні дані, що рендеряться у DOM (`innerHTML`), обов'язково проходять санітизацію через функцію `escapeHtml()`.
  - **CSV / Excel Formula Injection**: усі рядкові значення експортованих таблиць обробляються санітайзером `sanitize_spreadsheet_cell()`, який екранує потенційно небезпечні символи запуску формул (`=`, `+`, `-`, `@`, `\t`, `\r`).
* **Рольова модель (RBAC) та захист від стороннього доступу**:
  - Створення, зміна та видалення об'єктів (`facilities`) вимагають дозволу `generator:configure`.
  - Перегляд списку ролей захищено дозволом `users:manage`.
  - Валідація числових значень системних коригувань (`_parse_non_negative_float`) та перевірка дозволених статусів генератора.
* **Захист від витоків та DoS**:
  - Обмеження параметрів пагінації `limit` (`Query(..., ge=1, le=500)`) на всіх спискових ендпоінтах.
  - Ендпоінт перевірки здоров'я (`/api/health`) повертає мінімальну інформацію без витоку змінних оточення (`app_env`).
  - Санітизація заголовка `X-Forwarded-For` для захисту журналу аудиту від спуфінгу IP-адрес.
* **Захисні HTTP-заголовки**:
  - `Content-Security-Policy` (CSP)
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `X-XSS-Protection: 1; mode=block`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: geolocation=(), microphone=(), camera=()`
  - Обмеження CORS списком дозволених хостів `CORS_ORIGINS`.

## 🚀 Швидкий запуск

### 1. Локальний запуск (Development)

Вимоги: Python 3.14+
```bash
# Клонування репозиторію
git clone https://github.com/JhonDoelMe/SD-GEN016.git
cd SD-GEN016

# Встановлення залежностей
pip install -r backend/requirements.txt

# Копіювання конфігурації
cp .env.example .env

# Застосування міграцій бази даних
alembic upgrade head

# Запуск серверу розробки
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

Відкрийте браузер:
- Веб-додаток: [http://localhost:8000](http://localhost:8000)
- Документація Swagger API: [http://localhost:8000/docs](http://localhost:8000/docs)

**Первинний вхід:**
- Логін: `superadmin`
- Пароль: `SuperAdminPass123!` (або заданий у вашому `.env`)

---

### 2. Запуск у Docker / VPS (Production)

```bash
# Створіть та налаштуйте .env
cp .env.example .env

# Запуск контейнерів
docker compose up -d --build
```

Система автоматично підніме:
- Додаток FastAPI (порт 8000)
- Базу даних PostgreSQL 16
- Nginx Reverse Proxy (порти 80, 443)
- Автоматично застосує міграції Alembic і створить початкового системного адміністратора.

## 🧪 Автоматизоване тестування

Проект покритий повним набором автоматизованих тестів (`pytest`):
```bash
python -m pytest backend/tests -v
```

Тестовий набір (25 тестів) верифікує:
- Створення та вхід початкового адміністратора;
- Стійкість до Brute-Force перебору та блокування (429 Too Many Requests);
- Серверну валідацію логінів, паролів та захист від XSS/SQLi у полях користувачів;
- Права доступу ролей (RBAC) та заборону несанкціонованих операцій;
- Захист ендпоінтів об'єктів (створення/видалення вимагає дозволу);
- Роботу HTTP security headers та безпеку ендпоінта `/api/health`;
- Роботу сесії «Запам'ятати мене» (Remember Me) та HTTP-Only Cookies;
- Майстер налаштування, життєвий цикл генератора та швидке оновлення параметрів;
- Серверні перевірки робочого графіка за часом Києва;
- Зупинку генератора у будь-який час та незменшуваність мотогодин;
- Оприбуткування палива та розрахунок ціни за літр;
- Переміщення палива в бак, захист від від'ємного залишку та переповнення;
- Регламентне ТО з подовженням інтервалу та проміжне ТО;
- Життєвий цикл дефектів та блокування пуску при критичних аваріях;
- Системні коригування SuperAdmin та їх незмінну фіксацію в аудиті;
- Формування аналітичних звітів та багатосторінковий експорт в Excel (.xlsx);
- Вимкнення застарілого CSV-експорту з поверненням коректного статусу (400 Bad Request);
- Працездатність ендпоінта живого моніторингу сервера `/api/v1/system/status`.
